# MS-Swift 微调诊断：DER、中文标签与复读后的恢复

审计日期：2026-09-15。以 MS-Swift 的三份截断输出为主要证据，早期实验仅作旁证。本轮使用留存数据和预测，完成 CPU 重评分与文本对照，没有重新推理或修改训练目标。

循环起点的进一步复核见 [MS-Swift 循环起点精确复核](MS-Swift循环起点精确复核.md)：按生成时间戳定位为 overlap 的有 2 例，另 1 例缺少首个循环字的声学时间。可定位案例为 2/2，不应把待定案例算成非 overlap，或把全体比例直接写成 100%。

**主要判断：现有证据支持“微调后更难退出异常重复、恢复格式及后续转录”这一假设。它尚不能证明过拟合、teacher forcing 或某个错误 token 是唯一根因。**

## 1. MS-Swift 的三个重点案例

### R8005_M8009，Step 20：Base 也会出错，但能退出

参考标签在该位置为：

> ……就买那假一赔十的，买的时候问你是假一赔十吗是，哎这个可以买。

Base 与 SFT 都在“就买那假一赔十的，”后错误地输出“外”。

| 同一位置的行为 | Base | MS-Swift Step 20 |
|---|---:|---:|
| 连续“外”的个数 | 75 | 48,230 |
| 能否结束这段重复 | 能，随后输出句末及结束时间 [993.91] | 未能退出，达到输出上限 |
| 能否继续其他语句 | 能，后续继续约 985 秒及以后的说话人语句 | 无后续正常语句 |
| 整场输出 token 数 | 32,393 | 65,536 |
| 正常 EOS / 截断 | EOS / 无截断 | 无 EOS / 截断 |

已核验相同音频、23,500 个初始 prompt token、相同 prompt token 哈希、vLLM、BF16、greedy、repetition_penalty=1、上下文和生成上限；引擎配置除模型权重路径外相同。

这是目前最有力的自然对照：**Base 已经存在局部异常重复，SFT 将能够退出的异常放大为持续循环。** 但两模型在此之前的完整生成历史不同，因此还不是固定前缀的因果实验。“恢复”只表示继续识别后续语音，Base 并没有把前面 75 个错字改正确。

### R8005_M8008，Step 20：失去说话人/正文结构，不是该片段内的负时长

实际输出格式为：

~~~text
[本句开始时间][说话人]本句正文[本句结束时间]
[下一句开始时间][下一说话人]下一句正文[下一句结束时间]
~~~

将用户指出的片段按该格式拆开：

~~~text
[1458.48][S02]对，生鲜配送这个是可以的。[1460.65]
[1458.70]  ← 下一句开始
[1458.88][1458.88][1458.88]……  ← 未进入说话人及正文槽位
~~~

1460.65 是上一句结束，1458.70 是下一句开始。两句话重叠时，下一句开始可以早于上一句结束。上一句本身的时长为 1460.65−1458.48=2.17 秒，没有负时长。即使把后两个数看作一对，1458.88 也晚于 1458.70。

Base 在同一位置给出的直接对照是：

~~~text
[1458.58][S02]对，生鲜配送这个是可以的。[1460.71]
[1458.81][S03]没有，我从我从山东买的。[1461.41]
~~~

Base 同样从前句结束的 1460.71 回到下一句开始的 1458.81，但能继续。参考中对应语句为：

~~~text
[1458.00–1461.42] S03：哦没有我从我从山东买的。
[1458.64–1460.63] S02：对生鲜配送这是可以的。
~~~

因此，目前最准确的观察是：**SFT 在新语句的开始时间后，生成了另一个时间戳，缺失说话人和正文，随后反复输出同一时间戳直到截断。** 1458.88 还与前文 S04 语句的结束时间相同，可作为“此前边界值被反复续写”的候选线索，但没有 logits/干预实验，不能证明复制机制。

这一区间确有多人重叠，可能增加段落切换难度；不能把跨语句的合法时间回退当作错误触发，也不应强制所有相邻时间数字递增，否则会破坏重叠语音表达。

### R8003_M8001，Step 40：Step 30 尚能恢复完整结构

Step 30 的相应续写：

~~~text
……[1328.27]
[1321.91][S03]都是公众场合儿，对。[1323.41]
~~~

Step 40 的相应续写：

~~~text
……[1328.27]
[1321.81][1322.01][1322.01][1322.01]……
~~~

同样是开始时间后没有进入说话人/正文格式。约 1322 秒的参考标注有 3 人同时说话；生成锚点前后 5 秒内，重叠时长占 62.7%，整场约为 16.1%。这是重点排查位置，但一个局部例子不足以证明 overlap 富集。

Step 40 前文把参考“老师也也是害怕的”说成“不太怕”，但 Step 30 也出现“不太怕”并能继续。因此单个语义错误并不是这个案例中已证明的充分触发条件。

## 2. 能否解释为错误生成之后缺乏纠错能力

**可以作为重点假设，更精确的名称是“错误或异常历史下的恢复能力下降”。**

自回归生成通常不能擦除已输出的错误。这里希望它做到的是：结束异常片段、回到合法的时间戳/说话人/正文结构、重新跟随后续音频，而不是在原地持续循环。

MS-Swift 证据包含两种形式：

- 文字循环：Base 和 SFT 都出现“外”，Base 能结束，SFT 不能。
- 结构循环：正常应接说话人标记的位置生成时间戳，之后未恢复结构。Step 20 的 R8005_M8008 和 Step 40 的 R8003_M8001 都有该现象。

普通 teacher-forced CE 计算的是在正确历史标签条件下预测下一 token 的误差；自由生成使用模型自身历史。现有 dev loss 没有直接测量“喂入错误或循环前缀后能否恢复”。因此 loss 降低与少数自由生成轨迹的恢复变差可以并存。

研究观察过重复历史的自我强化，也观察过语言模型从失真前缀中自行恢复，说明 teacher forcing 并不必然导致无法退出的循环。这些研究支持提出假设，不能直接证明本 ASR 模型的因果机制。[Learning to Break the Loop，NeurIPS 2022](https://arxiv.org/abs/2206.02369)；[Exposure Bias versus Self-Recovery，EMNLP 2021](https://aclanthology.org/2021.emnlp-main.415/)。

要验证，建议优先在上述三个 MS-Swift 案例做前缀干预，保持整场音频、模型、后端和解码设置一致：

1. 从同一人工核对位置输入正确前缀，短续写 256–512 token。
2. 输入实际失败前缀；另建只修复局部异常的前缀。M8008 优先比较在开始时间后补入说话人标记是否足以恢复，以及补入完整正确短句是否恢复。
3. 对“外”分别注入 1、2、4、8、16 次重复；Base、Step 20、Step 40 使用相同干预前缀，比较退出循环的能力。单独考察文字与结构错误，保留足够上下文和生成预算。
4. 记录合法结构恢复、循环逃逸所需 token 数、后续固定语音窗口的转录覆盖率；获取 logits 时再比较继续重复与正确后续/句末 token 的概率。提前 EOS 不算成功恢复。

这些干预尚未执行。若正确前缀可正常继续、错误前缀失稳、局部修复能挽救，且 SFT 比 Base 更敏感，才有更强的因果证据。若正确前缀也失稳或修复无效，仍需查声学信息利用、边界建模与缓存推理一致性。

当前 full-attention 对照组继续保留标准 CE。上述诊断可以延续到 masked-KV SFT 和熵 RL，不必先改变训练目标。

## 3. DER 补充评分已完成

CPU 作业 63646 对正式 test-20 的 56 场会议、112 份 Base/SFT 输出重评分，约 3.17 分钟完成，无需重新推理。包含 overlap 的 DER 已复现原正式结果。

DER =（漏检说话人时长 + 误报时长 + 说话人混淆时长）/ 参考说话人总时长。使用相同 RTTM、UEM、pyannote 说话人映射和 collar 参数 0.25；各语料库累计时长计算，非会议 DER 简单平均。

原结果已有 collar 0 与 0.25、包含 overlap 的 DER；此次增加排除 overlap 的版本。

| 测试集 | 包含 overlap：Base → SFT20 | 排除 overlap：Base → SFT20 |
|---|---:|---:|
| AMI | 22.22% → 16.35% | 13.22% → 8.50% |
| AliMeeting | 7.77% → 14.24% | 2.42% → 6.44% |
| AISHELL-4 | 5.92% → 6.10% | 4.82% → 5.06% |

排除 overlap 后 AliMeeting 仍明显退步，因此错误影响不限于重叠区。但如果循环由 overlap 触发，它仍会造成后续非重叠语音的漏检；上述结果不能排除这种传播路径。两列的计分区域、分母及可能的映射不同，不能直接相减当作 overlap 贡献比例。

AliMeeting 包含 overlap 的漏检项由 5.90% 升到 12.57%；误报约 1.34%→1.21%，混淆约 0.52%→0.46%。主要增加的是漏掉的说话人时长。

成对去掉 M8008、M8009 仅作诊断，余下 18 场仍退步：包含 overlap DER 6.53%→10.10%，排除 overlap DER 2.33%→4.41%，cpCER 13.54%→17.11%。正式成绩仍使用全部测试会议。

## 4. 中文标签及编码

已检查全部 536 场训练记录：AMI 136、AliMeeting 209、AISHELL-4 191。中文共 400 场，占约 74.6%；中文 target token 约占 79.1%。

536 条转换后的音频路径、prompt、target 均与原始记录逐项相同；严格 UTF-8 通过；未发现 U+FFFD、NUL、空 target、目标结构不可解析、负时长或起始时间倒退。全部 target 经当前 tokenizer 编码/解码均逐字符相同。

**没有发现中文在数据转换、文字编码或 tokenizer 往返时被破坏的证据。** 这不证明人工听写、音文时间对齐、声学表征完全正确。参考转录里确有自然重复、口吃以及需要听音核实的语句；不能自动把重复文本删除。DER 依赖时间与说话人，中文字符规范化也不能单独解释 DER 退步。

## 5. 扩展案例仅作旁证

扫描留存结果，去除相同副本与 128-token 工程试验后，共 23 份完整推理截断输出、21 个会议/模型组合、13 场会议。其中 MS-Swift 3 份，早期 20 份；早期包含 step 10/20/25/50 及完整旧训练模型。

按稳定尾段分为文字周期循环 10 份、时间戳/结构循环 9 份、正文相同而时间戳推进 4 份。23 个生成锚点中，11 个落在参考 overlap；16 个前后 5 秒窗口含有 overlap，7 个窗口完全没有 overlap。按会议/模型组合合并，10/21 的锚点位于 overlap。

这些不是独立同分布样本，也不是词级强制对齐。数万个复读 token 属于同一个失败，不能计成数万个 overlap 事件。失败样本缺少正常位置的匹配对照，无法由此声称“大部分复读 token 在 overlap”或给出 overlap 的因果风险。

两条有用的历史旁证：

- R8003_M8001：Base 同处输出 5 个“窃”后继续，早期 SFT 连续 55,506 个“窃”后截断。历史推理配置记录完整度低于 MS-Swift 对照。
- R8001_M8004 的“下下周”、AISHELL-4 的“这这这这”本来就在参考中，Base 能结束短重复并继续，SFT 持续重复。说明循环不要求第一个重复字就是错字，退出真实短重复也可能失败。

另有 AMI TS3004c 的 Mm. 尾段在参考最后一条语音结束约 50 秒后形成；尚未听音，不能据此认定该段实际音频完全静音。早期还存在 [Música]、[?] 等结构异常，不能强行归入与 MS-Swift 相同的原因。
