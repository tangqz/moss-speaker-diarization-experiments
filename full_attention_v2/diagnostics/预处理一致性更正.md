## 已确认的实现差异

历史评估 63363 和仓库生产入口 `generate_transcription` 在 CUDA BF16 autocast 内调用完整音频的 `prepare_inputs`；63421 的原 `generate.py` 在其外调用。音频特征提取显式运行于 CUDA，因此这不是无效的上下文差异。此前声称两条路径完全一致，需要更正。

63440 的同音频配对探针保持模型权重、生成设置、输入 token、attention mask、音频长度和 chunk mapping 相同，只改变预处理上下文。两种返回的 `input_features` 都是 float32，但最大绝对差 0.0011870265、RMS 差 0.0002605863，99.978% 的位置存在数值差异。

| 模型 / 预处理 | 512-token 结果 |
|---|---|
| base，原 v2 上下文 | 与 63439 前缀完全一致；与历史 63363 仅前 34 token 相同 |
| base，生产 BF16 autocast | 与历史 63363 的前 512 token 完全一致 |
| 第 10 步，原 v2 上下文 | 与原 63439 前缀完全一致，出现 21 个 `[?]` 标签 |
| 第 10 步，生产 BF16 autocast | 前缀轨迹改变，仍出现 21 个 `[Música]` 标签 |

这解释了已测 base 前缀差异的来源，但没有证明全部长循环由此引起，也没有证明完整生成已经恢复。短探针不计入正式六场或全 dev 验收。

## 修复与完整复评

`production_generate.py` 从冻结的原生成文件派生，只恢复完整会议 `prepare_inputs` 的 CUDA BF16 autocast 环境，并写入预处理元数据。精确差异见 `preprocessing_fix.diff`，原/修复后 hashes 见 `preprocessing_fix.json`。原 63421、63432、63439 输出不覆盖，保留为原 v2 预处理路径的诊断；其与历史 base 的差值不再视作纯训练效应或生产验收依据。

完整复评 **63441**：第 50 步原六场 sentinel，加 TS3004c 的原始 base 和第 10 步，共 8 项新生成。固定完整音频、BF16 模型与前向、full attention、greedy、EOS/pad、65,536 上限和原 parser/scorer。其结果目录为 `/work/qt28/moss/results/full-attention-v2-diagnostic-63441`。对六场原历史 base 的质量比较仍沿用原评分，另做同一 TS3004c 的完整 base token 序列比较。

完成时需要 8 个新生成无执行错误，三组评分分别 12/2/2 条完整；共享 base 的评分副本不算独立样本。保留质量失败，原条件不因修复而放宽。程序不会恢复训练；由完整结果决定后续处理。此前六场 teacher loss 的同协议趋势和真实训练日志仍保留。

## 延续到 full / mask / 熵 RL

- 明确区分训练/teacher 的既有 DataCollator 预处理与生产生成的预处理环境；本次未改变训练数据管线或重训。
- 所有生产生成对照必须使用同一输入构造入口与计算上下文；不能只凭最终 feature dtype 相同就认为特征相同。
- 后续 full / mask rollout 应共享同一音频特征与输入映射，保存其构造上下文和 hash。
- RL 的 old policy、reference 和更新后 policy 概率/熵核对须复用 rollout 实际输入特征；若重新计算，必须核验特征一致，不能在另一精度上下文中重建后直接比较。
- 学习率或 warmup 的单因素训练对照须在完整生产路径复评之后再决定；不为改善分数删去失败会议、裁音频尾段或更改 parser。
