## 本次证据支持什么

- 固定六场 teacher loss 从 0.5931 降到 0.4248，但同一生产入口下，第 50 步仍有 2/6 场达到 65,536 token 上限。
- AliMeeting cpCER 为 base 18.0413% / SFT 25.1156%；AMI 为 8.9708% / 15.5734%。DER .25 分别为 8.2830% / 15.8252% 和 12.2926% / 13.6158%。均保留失败计分，按字符/秒数汇总。
- TS3004c 的原始 base 全部 26,337 个生成 token 与历史逐个一致。第 10 步完整生产复核仍循环，cpCER 99.6092%；它在约 66.7 秒反复输出 Música 标签。失败不只发生在音频无标注尾段。
- 第 50 步 TS3004c 有 1,657 个相邻同文 Mm. 片段；R8001_M8004 有 51,141 个连续相同 token（下）。原“严重解析失读”指标未报警，必须同时看 EOS、原始输出和多种重复计数。

这些结果说明生成质量检查失败，也说明仅看 loss 不足以验收。它们没有证明学习率过大是唯一根因，没有确定退化的精确起点，更不能证明降低学习率一定有效。没有验证 loss 持续上升的证据，不能仅据这些曲线断言典型过拟合。

2. scheduler 从开始按 402 步定义，短停止由 callback 控制。保留第 1、5 步权重；第 10、25、50 步保留完整 optimizer / scheduler / sampler / 各 rank RNG，便于复核与后续合法恢复。保持训练状态、计算日志、teacher 结果与自由生成记录分开。
3. 第 10 步先做**完整 TS3004c** 的生产入口诊断，与 63441 的同一步数输出和已核实 base 比较。若截断、空输出或原严重解析失读门槛触发，停止该短对照；原始标签/文本/token 重复计数同时保存。不能用短前缀通过代替整场通过。
4. 第 10 步通过才继续到第 50 步，仍在第 25、50 步测同一六场 teacher loss，第 50 步生成原六场完整 sentinel。检查实际前 50 步监督 token 合计是否仍为 **4,076,380**，防止数据/分母变化被当作学习率效果。
5. 第 50 步不论通过与否，先结束这项短对照并报告。若灾难性输出消失，只说明早期稳定性证据改善；同时检查各语料 cpCER/DER 是否仍退步。该检查点不是正式模型选择候选，也不触发 test 调参。
6. 只有后续继续正式阶段，才按原规则在 134 / 268 / 402 步做全 26 场 dev 验收与选择；选模完成再进行原 56 场 test。保持原门槛、失败计分和检验集隔离。没有合格候选时如实报告。

如这项仍失败，结果应否定“仅将学习率缩至 1/5 已足够”的假设；再按证据设计独立 warmup 或声学信息利用诊断。不要自动扩大为超参数网格搜索，也不要为了消除重复而临时修改解码或生产评分。

## 延续到 mask KV SFT 与熵 RL

最终若采用新学习率，full 与 mask 两组需使用同一 base、数据顺序、监督 token、更新精度、batch、scheduler 与选择规则。这样 full 组仍是全参数、全注意力的 SFT 对照，唯一后续研究差异可以清楚归到 KV mask。

音频预处理计算环境纳入共同协议；只记录输出特征 dtype 不足以证明输入一致。生成应记录或散列实际输入特征、输入 IDs 和音频映射。熵 RL 的 old / ref / policy 概率复核复用 rollout 实际特征，或验证重新生成的特征一致；否则输入精度差异会污染概率比与熵比较。此要求是后续实现契约，不宣称当前所有 rollout 已逐项保存特征 hash。
