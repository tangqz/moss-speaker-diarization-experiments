## 1. 推荐方案与研究问题

采用 Unlimited OCR 的 Reference Sliding Window Attention（R-SWA）思想：**所有生成位置保留完整音频与指令参考，只限制输出历史；训练和推理使用同一可见性规则，推理实际淘汰过期输出 KV。**

第一轮训练三个同条件模型：Full Attention、R-SWA-128、R-SWA-256。全部从原始 MOSS Base 初始化，使用现有完整会议数据、全参数 SFT 和标准 next-token CE。先完成 30 步工程与适应性检查，再比较 150 步结果；预先约定条件满足时延长至最多 402 步。最佳窗口和 Full Attention 增加一个配对 seed 复核。

旧 baseline 的复读诊断暂停。新的 Full Attention 是本轮必要的同条件实验对照，其复读问题不作为 R-SWA 开始或继续的前提。旧 SFT、恢复 CE、UL 等结果保留为历史背景，不作为本轮初始化或训练目标。

本轮回答：

1. 缩短输出历史能否保持 CER、cpCER、DER 与转录完整性？
2. 在同一音频输入下，输出 KV 是否真正停止随生成长度增长，带来多少解码和端到端收益？
3. 只在推理时裁缓存与训练、推理均使用窗口，效果有何差异？
4. 说话人离开较久后重新出现、重叠语音、长句和时间戳是否受短窗口影响？

固定窗口是本轮完整研究范围。动态窗口、输入音频滑窗、说话人记忆库、RL 和辅助反复读目标留给独立后续实验。

## 3. 精确的注意力合同

### 3.1 前缀和窗口定义

单条序列为 `reference || assistant_target`，reference 长度记为 P，位置从 0 开始。P 是第一枚 assistant 目标 token 的位置，通过模板展开后保存的显式边界确定；训练时用 labels 的首个有效位置交叉校验，推理时由完整 prompt 长度确定。

reference 是 `[0, P)` 的全部 token，而不只是 `<|audio_pad|>`。reference 内部保持原始 causal 语义，不把音频前缀改成双向注意力。输出中的文字、时间戳、说话人标签和分隔符均计入 k，不额外保留早期输出标签或所谓 attention sink。

对有效 query 位置 i、有效 key 位置 j，允许注意力当且仅当：

```text
同一条样本，并且 j <= i，并且
    (j < P 或 j >= max(P, i-k+1))
```

因此：

- i<P：原有 causal prefix attention。
- i>=P：全部 reference，加上截至 i 的最近 k 个已输入输出 token。
- 使用 i 位置 logits 预测 i+1 的目标；自身 key 不等于泄漏下一枚标签。
- `k=128` 明确定义为：预测下一 token 时，最多使用 128 个已经输入的输出 token 的 KV，其中包含当前 query 对应的输入 token。
- `k>=输出长度` 时，与原始 full causal attention 等价。

第一次生成由最后一个 prompt token 的 logits 得到。缓存计数按已经 forward 的 token 定义，避免把“刚采样但尚未输入模型”的 token 计入 KV。

### 3.2 位置与缓存

每层保存两段：固定 reference KV + 容量 k 的输出 KV 环形缓冲区。缓存槽位可循环使用，**RoPE 的逻辑位置必须按原序列持续递增**。不因物理缓存变短重置 position IDs，也不把 reference KV 随输出移动或重新旋转。

区分并保存：reference_length、总已处理 token 数、有效输出 KV 数、ring 写指针、每个槽位的逻辑位置。`prepare_inputs_for_generation` 必须按总已处理长度切新输入，不能按物理缓存长度切，否则环绕后会重复输入旧 token。

首版支持 batch=1、greedy、单 token decode。分块 prefill 必须保留 prefix 内因果关系；带 teacher-forced 输出的 prefilling 必须逐 query 应用输出窗口。对于多 token decode，未验收前显式拒绝，不能先覆盖多个环形槽再让所有 query 看同一缓存。

### 3.3 训练语义

继续并行 teacher forcing，`use_cache=false`。对每个输出 query 应用上述 mask，损失仍是原生 CE。所有有效 assistant token 和原始 EOS 受监督；prompt/padding labels 为 -100。

训练期间不使用推理 ring buffer，不做截断反向传播，不 detach 历史隐藏状态，不用模型生成的文本替代真值。窗口限制的是每层的直接 attention；远处信息仍可通过中间隐藏状态间接传递，因此“修改任意远处历史后最终 logits 必须不变”不是正确的验收标准。

### 4.1 先建立数值参照，再优化

1. **正确性参照**：短序列 eager/SDPA math，显式 mask，FP32 核对前向和梯度。
2. **正式训练候选**：FlexAttention + BlockMask。mask 表达为 causal 与“reference 或窗口”的组合，避免创建 116K×116K 的 dense mask。
3. **推理**：完整 reference prefill，随后环形输出 KV；单 query 对所有有效缓存做一次统一 softmax。窗口满后禁止每步复制整个 reference。
4. **后备高效实现**：只有 FlexAttention 与当前环境不兼容时，评估 prefix attention 与局部输出 attention 分支，经 log-sum-exp 正确合并 softmax 分母；不能把两个独立 softmax 输出简单相加。该方案须同样通过梯度验收。

PyTorch 提供自定义 mask 与 BlockMask 接口，但仍将 FlexAttention 标为 prototype，因此不能事先保证它与现有 Swift SP4/FSDP 组合兼容。[PyTorch 文档](https://docs.pytorch.org/docs/2.14/nn.attention.flex_attention.html)

分块 mask 的构建本身也要做内存分析，不能为了生成稀疏索引先创建完整 dense 布尔矩阵。prefix 区是 causal 三角，output→prefix 是完整矩形，output→output 是因果带状区；块边界处继续执行精确 token mask。

### 4.2 SP4 的具体处理

现有 Swift 源码为 SDPA/FA 包装了 `DistributedAttention`，FlexAttention 并不会因为设置 SP=4 自动接入。需要显式复用 QKV all-to-all 路径，在得到全局序列坐标后的局部 head 计算中执行 R-SWA，再逆变换输出。

默认正式拓扑保留 **4×A40、SP=4、DP=1、FSDP1、activation CPU offload**，以覆盖现有完整长会议。先在单卡短样本建立参照，再逐步验证 SP2/SP4；不能把更早“优先 DDP”的建议当作本轮 116K 样本已经能在单卡运行的证据。

关闭旧 `MOSS_IMPLICIT_CAUSAL=1` 的省略掩码捷径；保留必要的单调位置和右侧 padding 对齐，但真实长度、prefix 边界、padding mask 由新实现显式管理。尾部填充不能进入 reference 或污染真实输出。

若 SP4 稀疏实现未通过，只能将结果停留在工程验证阶段，继续修正或提交资源/拓扑修订；不静默切短会议、删除最长样本、冻结音频塔或修改 loss。

### 4.3 主流推理引擎

先以同一 HF/Transformers 路径完成 Base/Full/R-SWA 的功能对照，再适配当前冻结的 vLLM MOSS 实现，用作主要批量评测与性能运行环境。

引擎需要分别保证：每请求完整 reference 的驻留、输出块回收、逻辑位置、GQA 布局、多模态输入顺序及 request 隔离。仅设置全局 `sliding_window=k` 会滑掉 reference，不满足本方案；仅加 mask 而不释放历史 KV，也不满足缓存目标。

HF↔vLLM 对齐通过后，主表使用同一 vLLM 后端重算所有比较组。若适配未完成，提交同一 HF 后端的科学实验结果，并把生产后端单列为未完成；不使用 HF R-SWA 对比旧 vLLM baseline 得出加速结论。

| 优化器 | 原生 AdamW；β=(0.9,0.999)，ε=1e-8，weight_decay=0，clip_grad_norm=1 |
| 学习率 | **1e-7**，linear，warmup=0，衰减尺度固定 402 updates |
| 有效 batch | 每次 optimizer update 4 场会议；SP4/DP1 时 microbatch=1、累积4 |
| 序列 | 完整会议，max_length=131072，packing=false |
| 并行 | 目标 SP4 + FSDP1 + activation offload；先通过上述关卡 |
| 主 seed | 0；最佳窗口与 Full 增加配对 seed=1 |
| 主预算 | 先到30，再到150；满足预设条件后，各可继续到最多402 |

按用户要求将共同初始学习率从1e-6降低一个数量级至 **1e-7**，Full-CE、R128-CE、R256-CE及后续配对seed全部一致。历史低LR run也使用1e-7，但其结果仍作为背景单列，不能据此称该学习率已被验证最优。首轮不同时做LR搜索，以免窗口结果与超参选择混合。若全部新模型适应不足或失稳，结论先限定于本轮配置，再提出下一轮成对LR实验，不在test上调参。

以536条数据、有效batch4计算，134 updates≈1 epoch，150≈1.12 epochs，402=3 epochs。30步是适应性与运行检查，不能凭30步失利否定该方法。

### 8.2 检查节奏

- 每步：train CE、LR、梯度范数、输入/目标 token 数、峰值显存、速度。
- 每10步及阶段终点：保存可恢复 checkpoint；额外保存 step5 便于早期回退。
- 每10步：固定 dev sentinel 小集完整自由生成。预先从 dev 按语料、时长、说话人数和重叠情况选6场，不能根据模型输出换样本。
- 完整26场 dev + teacher-forced CE：step0、30、100、150；若延长，再于268和402运行。阶段异常时可补一次完整dev核验。
- 初期 sentinel 只用于预警，不把6场结果标成完整dev。最终checkpoint只能从有完整26场dev结果的候选中选。

先运行 R128-CE 至30步，再运行 F-CE 至30步及 R256-CE 至30步，随后轮转推进。每组保存/恢复自己的optimizer、scheduler和RNG；同一更新数的数据清单一致。

### 8.3 延长、停止与复核

默认完成三组150步比较。若至少一个R-SWA组在step100→150的完整dev选择分数改善≥0.1个百分点，或者其相同口径dev CE相对下降≥1%且选择分数恶化不超过0.1个百分点，并且没有连续两次完整dev的灾难性失败，则将仍有效的三组按同预算继续至268/402；所有阶段保持402步scheduler，不重启衰减。到268步用同一规则比较150→268，决定是否继续402步。CE改善只决定是否值得追加适应预算，不作为模型质量合格的替代。

工程错误、NaN、缓存越界、错误split、实际训练mask失效立即停止对应任务并修正。单个dev复读保存证据，不立即回到旧baseline诊断；若一个组连续两次完整dev都出现确认的严重循环、截断或严重漏段，则停止该组后续昂贵扩展，并完整保留失败结果。Full组失效不停止其他组。

最高质量候选的建议资格门槛：无确认病态循环、无预算截断/空输出/大段解析损失，无严重提前EOS和漏段。没有任何候选合格时，结果写明未获得可用模型；仍可报告结构正确、缓存有界等工程结果。

dev选择建议：对AliMeeting和AMI分别计算cpCER和DER025，然后四项等权平均为S。先满足功能资格及逐语料非劣门槛，再最小化S；S差≤0.1个百分点视为效果接近，优先选端到端RTF更低者。CER、DER0、DeltaCP和所有原始指标同时保留，不让综合分遮蔽单项恶化。

seed0存在合格R-SWA候选并确定最佳k与训练上限后，用seed1对最佳k和F-CE做配对复核，执行同样预先冻结的选点规则；不再重新选k。没有合格R-SWA候选则先交付失败结论，不自动追加两个复核run。共三组主run加至多两组复核，最多 **5×402=2010 optimizer updates**，不含小规模工程检查。每步4场会议，最多8040次会议呈现。若只运行150步则最多750 updates。两seed是初步可重复性证据，不冒称充分刻画训练方差。

## 9. 测评协议

### 9.1 准确率与完整性

复用既有评分定义：CER、cpCER、DeltaCP=cpCER−CER；DER同时报告collar0和0.25秒，保留重叠语音，固定原RTTM/UEM。语料内按参考字符/说话人时间聚合，另外提供逐会议分布；英语主表继续使用CER，不改名为WER。

所有比较组使用BF16、batch=1、greedy、num_beams=1、相同EOS，**repetition_penalty=1.02**，presence/frequency penalty=0，无额外n-gram抑制。该设置同时覆盖Base、Full、R128/R256、仅推理窗口消融、dev监测与选点、最终Test及自由生成性能评测。总逻辑上下文保持131072，`max_new_tokens=min(65536,131072-P)`。本轮即使物理缓存变短也不突破原RoPE/逻辑上下文上限；不声称实现无限音频或无限位置外推。

repetition penalty的作用范围统一为该请求已生成的全部输出token，不包括输入reference；不随R-SWA的KV窗口截短。HF/vLLM需显式核对这一语义，不能仅凭同名参数相同便认为协议一致。历史token记录与KV缓存分开管理，其自身内存/处理开销照实计入性能记录。训练和teacher-forced CE不施加此解码惩罚。

评测配置及缓存复用指纹必须包含penalty值和作用范围。历史penalty=1的预测不能复用到本轮主表，Base亦须按新协议重跑；本轮观察到的稳定性属于R-SWA与统一解码设置共同作用下的结果，不单凭无复读认定窗口机制解决了旧问题。

每条输出保存原始token IDs、原文、解析片段、EOS/截断、异常、实际生成长度和停止原因。解析后准确率与未解析尾段、单token长重复、短周期重复、时间戳循环联合审计。自然口语重复不自动判失败。

检查按时间分桶的删除错误和语音覆盖、最后有效输出时间、异常长空洞；最后时间戳到达结尾不能单独证明没有漏段。质量统计使用自由生成，不能用teacher-forced轨迹代替。

计划最终对Z-Full、F-CE、R128-CE、R256-CE各自dev冻结的一个checkpoint进行完整56场Test；窗口的主胜者先在dev确定。seed1的Full与最佳k另做完整Test复核。至多6×56=336条模型—会议预测，不重复计算相同协议下已通过严格哈希核验的Base；旧不同引擎Base一律重跑。

测试模型的截断和坏输出进入原始质量报告，不删坏例美化指标。执行失败/OOM/超时不记成零错误率；报告完成覆盖率、失败明细及共同完成样本的配对统计。完整覆盖前不宣称测试完成。

### 9.2 说话人长程一致性

这是语音迁移相较OCR的主要风险：音频仍可见，但很早建立的声纹→Sxx编号对应可能不再直接出现在输出窗口内。

保留标准cpCER和DER为主指标，增加以下辅助分析：

- 按说话人离开后再出现的间隔分桶：<30s、30–120s、>120s。
- 对齐到参考语音后，使用整场统一说话人映射分析回归区间的speaker confusion；统计同一真实说话人被拆成多个预测编号的fragmentation。
- 按说话人数、重叠率、正文长度与会议前/中/后段分层。
- 无法对齐、未识别或无有效speaker的回归片段单列覆盖率，不从分母静默剔除。

这些是项目诊断指标，不称为新的标准benchmark。不得用每个片段单独重匹配说话人掩盖长期身份漂移。

### 9.3 性能：两种互补测量

**端到端自由生成**：同GPU型号、同batch/concurrency、同精度与后端，统计音频加载/特征、prefill、decode、首token、总延迟、RTF、audio seconds/s、tokens/s、峰值显存、生成token数及失败率。模型加载、预热、编译分别记录，不计入主RTF。

**固定轨迹性能回放**：使用相同权重、相同音频和预先冻结的相同token续接，比较Full与R-SWA各输出长度的kernel耗时和KV曲线。各组同样计算1.02 repetition penalty并记录其开销，下一token由冻结轨迹提供。回放只回答计算效率，不能拿它报告识别准确率。它能排除提前EOS、漏转录或复读导致的输出长度差异。

回放长度建议1K/4K/8K/16K/32K，在逻辑上下文允许时补64K；无法达到的组合标为不适用。reference长度从真实train/dev取分位数样本。至少3次重复，报告中位数、p90及波动，预热和编译不混入。

batch=1为主要因果对比。并发1/2/4是后续吞吐测量，分别记录配置与OOM；不拿不同并发的结果作为窗口自身加速倍率。

### 9.4 理论预期与验收目标

在标准未量化BF16 GQA缓存下，MOSS的每token跨全部28层KV约为：

```text
2(K和V) × 28层 × 8个KV heads × 128维 × 2 bytes
= 114688 bytes = 112 KiB/token
```

因此纯输出区容量：k128≈14MiB、k256≈28MiB；20K历史输出KV约2.14GiB。这不包含reference、模型、音频激活、allocator和临时workspace。

缓存比率近似 `(P+min(k,T))/(P+T)`。例如P=40000、T=20000、k128时总KV约下降33.1%；若P=10000、T=30000约下降74.7%。它们是计算示例，不是实测承诺。reference本身随音频增长，prefill仍有P²级attention成本，训练复杂度仍包含P²和P×T项。

建议预注册以下**研究目标**，与代码正确性门槛分开：

- 所有层有效KV在窗口满后保持P+k，底层KV容量无随T持续增长；allocator reserved等其它开销另报。
- 相对新F-CE，每个dev语料CER/cpCER恶化不超过0.5个百分点、DER025不超过1.0个百分点；同时报告相对Base变化。这是建议的工程非劣容忍度，不是文献标准。
- 长输出桶固定轨迹decode时间目标降低≥20%；端到端RTF目标降低≥10%。达不到时如实区分“缓存目标达成”和“实际加速未达目标”。
- 报告配对会议bootstrap的95%置信区间（建议1000次重采样，各次重算聚合分数）。点估计在容忍度内不等于统计证明非劣；上置信界仍越过容忍度时写证据不足。

先给工作量级估计：P0–P2约2–4个工作日，P3约1–3个工作日；训练和长音频评估耗时由现场基准决定，排队另计。这是计划估计，不是已测工期。

正常恢复和预先约定的阶段推进纳入本次批准范围；若必须修改loss、冻结范围、数据划分、会议长度或超过上述训练上限，则先给修订依据，不悄悄改变实验问题。仅保留当前恢复点、最佳点和预先约定里程碑时，也需在新实验目录内部执行，不触碰旧历史成果。

服务器执行沿用用户要求的可见交互终端，持续留存实际命令输出和日志。检查已有作业和配额后再提交，不自动取消其它任务。本轮计划确认前不登录执行模型改造，不提交训练/评测作业。
