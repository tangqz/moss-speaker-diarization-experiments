评测作业 `63787`，原始结果位于远端 `.../evaluations/problem-R8005_M8009-step-30/`，本地独立审计为 `dkucc/local_ul30_analysis/c30_audit.json`。

- Base：32393 tokens，EOS=true，未截断，最长同 token 连续 75，最大时间戳 1773.11s，CER 49.08%、cpCER 41.85%，参考语音区间未覆盖约 11.15s / 0.642%。

- C 的 CER=70.5427%、cpCER=65.6518%、删除数=8126；相对 Base 分别恶化约 21.46 和 23.80 个百分点。
- 门禁结果：`passed=false`，原因是 `output_cap_truncation`、`missing_eos`、`raw_token_repetition`、`premature_transcript_end`；自动停止，不再继续 60/150 步。

结论：在固定已知难例、学习率 1e-6、30 步和当前局部 UL 事件协议下，`恢复 CE + UL` 没有解决复读，且比 Base 明显恶化。训练日志中第 30 步附近 UL 平均值已降至约 0.000238，但自由生成仍进入长循环，说明训练事件上的局部 UL 信号没有转化为该问题样本的稳定生成行为。由于本轮 C 已明确失败，按预设资源策略不追加 B 对照；不能据此声称 UL 相对恢复 CE 没有增量收益，只能判定当前方案未达到目标。
