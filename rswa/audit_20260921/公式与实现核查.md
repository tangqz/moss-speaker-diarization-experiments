# MOSS R-SWA 公式与实际实现核查

核查日期：2026-09-21。范围是第一轮与第二轮服务器实际部署的代码，以及实际安装的 Transformers、Swift 和 vLLM。此次只读取实验文件、运行 CPU 检查并保存核查材料，没有修改训练或推理实现。

## 结论

**正式路径实现了论文的注意力可见性：完整 reference 加最近 k 个已输入的输出 token。`max(P, i-k+1)` 正确，没有发现下标差一位、reference 被窗口裁掉或训练看到未来目标的问题。**

发现两项具体问题：

1. 正式 vLLM Triton 内核虽然正确屏蔽历史、回收 KV 页，仍遍历全部逻辑历史位置。注意力结果的数学定义正确，但未完整实现论文所强调的固定解码注意力计算量。
2. 可选 `dense` 调试后端不能直接与回卷后的 ring cache 混用。该问题可以复现；当前正式配置的训练 Flex、推理 Triton 及默认 HF 单 token 路径不经过这个错误分支。

这些证据支持“正式注意力规则实现正确”，不等于证明 R128/R256/R512 必然适合长会议 ASR 和说话人日志，也不证明全部 BF16 数值误差均可忽略。

## 1. 与论文公式对齐

论文 [§3.4.1，式 (1)–(4)](https://arxiv.org/html/2606.23050v1#S3.SS4.SSS1) 使用从 1 开始的 token 位置。预测第 t 个输出时，前缀长度为 P，输出可见区间为：

\[
\max(P+1,\ P+t-k)\le j_{\mathrm{paper}}\le P+t-1.
\]

代码从 0 编号，并使用输入位置 i 的隐藏状态预测下一个 token。因此：

\[
i=P+t-2,\qquad j=j_{\mathrm{paper}}-1.
\]

代入得到：

\[
\max(P,i-k+1)\le j\le i.
\]

这里的当前位置 i 已经是输入，真正要预测的位置为 i+1。允许 `j=i` 是标准 next-token prediction，不是泄漏目标。

完整规则为：

\[
M(i,j)=\mathbf{1}\{j\le i\}\,\mathbf{1}\{j<P\ \lor\ j\ge i-k+1\}.
\]

- 当 i<P，规则退化为原来的 causal prefix attention，即只看 `[0,i]`。
- 当 i≥P，完整前缀 `[0,P)` 与输出区间 `[max(P,i-k+1),i]` 取并集。
- `max` 只把输出区间限制在输出区域，**没有删除前缀**；前缀由另一个并集分支独立保留。
- 前 k 个输出输入位置还不需要淘汰历史；此后始终保留恰好 k 个输出 KV。

例如 P=5、k=3，reference 为位置 0–4：

| 当前输入位置 i | 预测目标 | 额外可见的输出位置 |
|---:|---|---|
| 4 | 第 1 个输出 | 无 |
| 5 | 第 2 个输出 | 5 |
| 7 | 第 4 个输出 | 5、6、7 |
| 8 | 第 5 个输出 | 6、7、8 |

这些行都保留 reference 0–4。窗口单位是 tokenizer token，不是汉字、单词、句子或音频帧。

## 2. 代码逐项核查

下列路径相对于本核查目录的 `source/`，均为从服务器或官方来源读取的代码快照。

| 核查项 | 实际代码与结果 |
|---|---|

| 稀疏块边界 | `attention.py:45–83` 的 partial/full block 分类在 padding、非 128 对齐前缀和非零 query 起点下与逐 token 规则一致。 |
| 前缀 P 的确定 | `round2/moss_rswa_plugin.py:34` 在标签移位前取第一个非 -100 的位置，并核对完整目标和 EOS。P 包括展开后的音频 token、指令与 assistant 模板。 |
| 训练与推理输入边界 | `evaluate_generate.py` 比较 vLLM 展开后的所有 prompt IDs 与官方 processor；`evaluate_ce.py` 比较 prompt 长度和输入收据。vLLM 使用 `num_prompt_tokens` 传递固定 P。 |
| 因果标签对齐 | Swift `sequence_parallel.py:623` 先把标签向左移一位；`seq2seq_trainer.py:136–143` 将标签从模型参数中取出，交给 `trainers/utils.py:167` 的 SP CE，未再次 shift。CE 评估明确用 `hidden[lo:hi]` 对 `labels[lo+1:hi+1]`。 |
| SP4 位置与范围 | `attention.py:hf_attention` 在 attention 前以 AllToAll 恢复完整序列、拆分 head，因而 mask 使用全局位置，不把每张卡当作独立会议；attention 后逆变换。 |
| 全部 decoder 层 | Base 配置的 28 层均为 `full_attention` 类型；模型 adapter 把这一 mask mapping 传给每层。vLLM 将 Qwen3 Attention 构造改为 RSWAAttention，并有 28 层运行收据核验。这里的类型名称不表示实际仍使用 Full mask。 |
| 正式推理 mask | `vllm/v1/attention/ops/triton_attention_helpers.py:314–343` 为 `key<=query AND (key<P OR query-key<k)`，整数位置上与训练式完全等价。 |
| Softmax 与加权求和 | HF/Flex/SDPA 在 reference 和 output 的并集上做一次 attention；Triton 使用共享在线 softmax 累积后归一化，未把两段分别 softmax 后直接相加。Qwen3 缩放为 `head_dim**-0.5`；GQA 沿用原模型 head 分组。对应论文式 (3)、(4)。 |
| RoPE | Transformers Qwen3 先施加 RoPE，再写入 cache；`model_adapter.py:52` 和 vLLM runner 使用持续增长的逻辑位置。ring 槽位回卷不导致位置归零。 |
| HF cache 回收 | `round2/cache.py:32–52` 固定 prefix，输出写入 `P+ring_pos`，只回收输出槽。逻辑长度单独累计，容量 P+k。单 token 解码在所有已保留 K/V 上 attention。 |
| vLLM cache 回收 | `single_type_kv_cache_manager.py:626` 的 RSWAManager 只释放完整位于 prefix 与当前 window 间隙的页，保护跨 prefix 边界的页；释放边界略保守，可能多留页内少量已被 mask 的 token，不会少留合法 key。 |

HF ring cache 的物理顺序回卷后并不按时间排序，但这本身正确：K/V 配对同步置换，RoPE 已经作用于正确逻辑位置；对同一组 K/V 的求和不依赖存储顺序。

作者公开的 [HF 推理实现](https://huggingface.co/baidu/Unlimited-OCR/blob/07dea832e22aefee32ad281d4b80551282e1c168/modeling_deepseekv2.py#L1232) 也固定 prefill、在输出区 ring overwrite、先应用 RoPE，并对单 token decode 的保留缓存做联合 attention。它为上述解释提供额外佐证；这不代表已经检查到论文内部 Megatron 训练源码。

## 3. 发现的问题及影响

### 3.1 正式 Triton 路径的计算量仍随逻辑历史增长

在 `vllm/v1/attention/ops/triton_unified_attention.py:399–420`，调用 `compute_tile_loop_bounds` 时传入 `USE_MM_PREFIX or USE_R_SWA`。后者在 `triton_attention_helpers.py:184–204` 把循环范围设为完整 `seq_len`，再逐 tile 加载 K/V 和计算 QK；窗口外位置随后才被掩码排除。没有跳过 prefix 与当前窗口之间的整段空洞。

对该部署版本的循环边界函数做 CPU 语义检查，固定 tile=32 时，逻辑长度 512、4096、65536 分别遍历 16、128、2048 个 tile。三维分段 kernel 会分摊循环，但所有分段的总工作仍覆盖逻辑序列。这是代码复杂度判断，不是新跑出的 GPU 吞吐基准。

影响：

- 不改变合法 key 集合，不能单凭它解释识别质量崩坏。
- 活跃 KV 页确实有界，但 kernel 的遍历/计算没有完全做到 O(P+k)。
- 不能据此声称已经复现论文的恒定解码 TPS 或全部性能性质。逻辑 block table 等元数据也仍随长度增长。
- 若后续做性能实验，应先让 kernel 直接遍历 prefix 与 tail 两段，或构造紧凑的合法 KV tile 索引。只改 token mask 不够。

论文式 (6) 描述 token KV 数；vLLM 的物理页分配还存在页对齐和保守保留开销，不能把 P+k 当成它逐 token 精确的 allocator 上限。

### 3.2 非正式 dense 调试分支与 ring cache 不兼容

`round2/attention.py:91–92` 在单 token cache 快路径之前进入 `dense_reference`。该函数以 `arange(k.shape[-2])` 当作 key 的逻辑位置；ring 回卷后，这实际是物理槽位编号，会屏蔽错误的 key。

最小复现 P=17、k=4：前 4 个输出 KV 的误差约 1e-7（dense helper 内部转 FP32 softmax）；第 5 个开始回卷，最大输出差异升至 0.0823，后续可达 0.4149。记录见 `dense_debug_result.json`。

正式训练默认 `backend=flex`，正式质量推理为 `TRITON_ATTN`，HF 默认解码使用 `attention.py:95–97` 的单 token 路径，因此未发现该调试问题污染已有正式实验的证据。后续不要将 dense+ring 组合作为正确性基准；可把 cache 快路径提前，或让 dense helper 接收真实逻辑 key 位置后再启用。

## 4. 与论文相同的原则，以及不能直接等同的部分

相同的是注意力邻域、联合 softmax、固定 reference、输出 KV 淘汰、各 decoder 层使用窗口，以及 next-token 因果约束。窗口外信息仍可能间接存在于较近 token 的隐藏状态；限制直接读取的 K/V 不等于禁止一切长程信息传递。

“reference 固定”指一次生成内，已算好的 reference KV 不随输出循环被改写或淘汰；它不要求训练时冻结音频 encoder。论文冻结视觉 encoder、我们的实验采用全参数训练，是训练策略差异，不是 attention 公式错误。[论文 §4.2](https://arxiv.org/html/2606.23050v1#S4.SS2)

论文采用 OCR 数据、不同底座和更大的适应训练预算。官方当前推理示例还有滑窗 no-repeat-ngram 处理；我们的配置只有输出侧 repetition penalty=1.02。这些差异不改变上述 mask 等价性，但使质量/复读表现不能直接视为论文结果的复现。[官方推理示例](https://github.com/baidu/Unlimited-OCR#inference)

ASR 加说话人日志还需要持续追踪同一说话人的标签、时间戳和覆盖进度。完整音频可访问并不意味着有限输出窗口下必然保持这些状态。窗口是否足够、学习率和预算是否合适，仍是实验假设；当前代码核查没有把这些机制认定为失败根因。
